# rename_images.py — 批量连续编号重命名图像

一个简单、安全的 Python 脚本：把某个文件夹里的**图像文件**批量重命名为**连续编号**，并且**后缀保持不变**（`.jpg` 仍是 `.jpg`，`.png` 仍是 `.png`）。

## 功能亮点

- ✅ **连续编号且无空洞**：起始编号自定（例如 `10345`），依次 `10345.*`、`10346.*`、`10347.*`……
- ✅ **绝不覆盖任何文件**：目标编号一旦与已存在的文件冲突（包括另一个还没来得及改名的待处理文件），自动向后递增，改用下一个空闲编号。
- ✅ **后缀保持不变**：只改文件名主体，扩展名原样保留。
- ✅ **默认 dry-run（预览）**：不真正执行，先打印将发生什么；确认无误后加 `--apply` 才真正改名。
- ✅ **支持子文件夹递归**与**自定义扩展名**。

## 环境要求

- Python 3（无需安装任何第三方库，仅用标准库）

## 快速上手

```bash
# 1. 预览（会打印将执行的重命名，但不会真的改动文件）
python rename_images.py

# 2. 确认结果无误后，真正执行
python rename_images.py --apply
```

> 脚本默认处理「**当前文件夹**」。不加路径，就是运行脚本时所在的那个目录。

## 两种编号模式

脚本提供两种"遇到编号冲突"时的处理策略：

| 模式 | 参数 | 冲突处理 | 结果编号 |
|------|------|----------|----------|
| **默认（跳号）** | 不加参数 | 目标号被占用就向后递增，改用下一个空闲号 | 可能留空洞 |
| **强制连续** | `--consecutive` | 先把占着目标位的文件临时挪走，再依次落位 | 100% 连续、无空洞 |

### 默认模式（跳号）——简单、安全
遇到目标编号已被占用，直接跳到下一个空闲编号。实现最简单，但被占用的号码会空出来，最终编号可能不连续。

### 强制连续模式（`--consecutive`）——无空洞
**要做到编号绝对连续，必须先给冲突文件"让位"**：第 `k` 个文件的目标位固定为 `起始号 + k`，凡是"当前名字恰好是别人目标位"的文件，先用唯一临时名（如 `.__room_…`）挪开腾出位置，等所有目标位空闲后，再逐个改写为其最终目标名。

```bash
# 连续模式：先预览
python rename_images.py --consecutive

# 连续模式：真正执行
python rename_images.py --consecutive --apply
```

> 两阶段均不会覆盖任何文件：临时名、目标名两两唯一，执行期间每步都先确认目标位置空闲再写入。

## 用法与参数

```
python rename_images.py [--start 起始编号] [--apply] [--recursive] [--consecutive] [--ext 扩展名] [文件夹路径]
```

| 参数 | 含义 | 默认值 |
|------|------|--------|
| `--start N` | 起始编号；文件依次分配 N, N+1, N+2… | `10345` |
| `--apply` | **实际执行**重命名；不加则只预览 | 仅预览 |
| `--consecutive` | **强制连续编号**（无空洞，冲突文件临时让位） | 默认跳号 |
| `--recursive` | 递归处理所有子文件夹 | 只处理顶层 |
| `--ext 后缀` | 追加识别一种扩展名（如 `.heic`） | 见下方默认扩展名 |
| `文件夹路径` | 要处理的文件夹 | 当前文件夹 `.` |

**默认识别的扩展名：**

```text
.jpg  .jpeg  .png  .gif  .bmp  .webp  .tiff  .tif  .ico  .jfif
```

## 完整示例

```bash
# 预览当前文件夹，起始编号 10345（默认跳号模式）
python rename_images.py

# 指定起始编号 + 指定文件夹，预览
python rename_images.py --start 1000 "D:\照片"

# 真正执行：当前文件夹，从 10345 开始
python rename_images.py --start 10345 --apply

# 强制连续编号，真正执行（冲突文件会自动临时让位）
python rename_images.py --start 10345 --consecutive --apply

# 含子文件夹 + 额外识别 .heic + 连续编号，真正执行
python rename_images.py --start 1 --apply --recursive --consecutive --ext .heic "D:\照片"
```

## 冲突是怎么处理的？

原始文件本身往往已经带编号，可能和你想要的编号段重叠。例如文件夹里有 `10345.jpg`、`10346.png`、`20000.jpg`，起始编号为 `10345`：

| 处理顺序 | 目标号 | 发生了什么 | 结果 |
|----------|--------|-----------|------|
| `10345.jpg` | `10345.jpg` | 撞到它自己（待处理文件），向后探测 | 改为 **10347.jpg** |
| `10346.png` | 游标已推进 | 探测到空闲号 | 改为 **10348.png** |
| `20000.jpg` | 下一个空闲 | 直接取名 | 改为 **10349.jpg** |

最终：`10347 / 10348 / 10349` —— **连续、无空洞，且从未覆盖任何文件**。

核心原则：**发现目标名已存在就跳号，先把已存在的文件安全留在原位**，稍后它自己也会被改名到后面的空闲号，因此没有文件丢失。

### 连续模式的冲突例子（`--consecutive`）

同样文件夹 `10345.jpg`、`10346.png`、`20000.jpg`，起始 `10345`。此时**不允许跳号**，必须让位：

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | `10346.png`（占着 10346 目标位）→ 临时名 | 先挪开腾位 |
| 2 | `10345.jpg` → `10345.jpg` | 它正好就位在此，无需动 |
| 3 | `20000.jpg` → `10346.png` | 目标位已空闲，落位 |
| 4 | 临时名 → `10347.jpg` | 占位文件落回它自己的目标位 |

最终：`10345.jpg / 10346.png / 10347.jpg` —— 整段无缝，无空洞、无覆盖。

## dry-run（预览）与 apply（执行）

- **不加 `--apply` = dry-run 预览**：脚本只打印"每个文件将变成什么名"，**不真正改动任何文件**；注意 `--consecutive` 模式还会打印"让位"步骤。
- **加 `--apply` = 真正执行**：才实际重命名。
- 建议流程：**先预览 → 核对 → 云端备份 → 再加 `--apply` 执行**。

## 安全与使用建议

1. **先运行预览**（不加 `--apply`），核对打印结果无误后再真正执行。
2. **正式执行前建议备份**（尤其文件较多时），毕竟重命名不可一键撤销。
3. 如果你希望按别的顺序分配编号（例如按文件大小、修改时间，而非文件名自然排序），可以告诉我，脚本可调整。
